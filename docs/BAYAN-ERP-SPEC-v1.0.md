## 1. Зорилго ба хамрах хүрээ

### 1.1 Нэг өгүүлбэрээр

Bayan AI-ийн **давхар бичилтийн immutable ledger цөм** дээр ОЧ 7.7-гийн 9 системийн
хамрах хүрээг барьж, гэхдээ AI-г маркетингийн бүрхүүл биш **өгөгдөл оруулалтын
автоматжуулалтын хөдөлгүүр** болгосон, SaaS загвараар зардлыг 10 дахин бууруулсан ERP.

### 1.2 Байр суурийн ялгаа

| | ОЧ 7.7 | **Bayan ERP** |
|---|---|---|
| AI-ийн үүрэг | Тайлан **уншиж** тайлбарлана (таамаглал + Q&A) | Тайлан **үүсгэх ажлыг хийнэ** (хуулга→журнал автоматаар) + уншиж тайлбарлана |
| Мөнгө оруулах зам | Нябо гараар шивнэ | Хуулга/падаан upload → AI ангилалт → нябо зөвшөөрнө |
| Худалдан авалт | ₮330сая нэг удаа + 15%/жил | Сарын захиалга, модулиар |
| Нэвтрүүлэлт | 3–10 хоног, зөвлөх баг | Өөрөө эхлэх (self-serve) + сонголтоор нэвтрүүлэлт |
| Мобайл | ХН модульд ₮10–20сая нэмэлт | Бүх багцад үнэгүй |
| API | "интеграц" гэж бичсэн, баримт бичиггүй | Нийтэд нээлттэй OpenAPI + webhook |
| Нотолгоо | ROI тооцоолуур (таамаглалд суурилсан) | Инвариант тест, GL-assertion, нээлттэй changelog |

### 1.3 Хамрах хүрээнд ОРОХГҮЙ (v1.0)

## 3. Архитектур

### 3.1 Давхаргууд

```
┌─────────────────────────────────────────────────────────────┐
│  Клиент: Web (React) · Mobile (ажилтан + Vanseller) · POS   │
└───────────────────────────┬─────────────────────────────────┘
                            │  OpenAPI 3.1 + Webhook
┌───────────────────────────┴─────────────────────────────────┐
│  ХЭРЭГЛЭЭНИЙ ДАВХАРГА — домэйн модуль (M1..M8)              │
│  Бүх модуль GL рүү ЗӨВХӨН post_entry()-ээр бичнэ            │
└───────────────────────────┬─────────────────────────────────┘
┌───────────────────────────┴─────────────────────────────────┐
│  AI ДАВХАРГА (3 түвшин — §5)                                │
│  L1 задлалт/ангилалт · L2 таамаглал · L3 асуулт-хариулт      │
│  Бүгд ledger-ийн READ-ONLY төсөөлөл дээр, эрхийн шүүлттэй   │
└───────────────────────────┬─────────────────────────────────┘
┌───────────────────────────┴─────────────────────────────────┐
│  ЦӨМ — Immutable double-entry ledger                        │
│  G1–G7 инвариант DB trigger түвшинд · amount_minor bigint   │
│  Бүх бичилт reversal-аар л цуцлагдана, UPDATE байхгүй       │
└───────────────────────────┬─────────────────────────────────┘
┌───────────────────────────┴─────────────────────────────────┐
│  ИНТЕГРАЦ — банк · eBarimt PosAPI 3.0 · QPay · e-Mongolia   │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 Архитектурын 5 хатуу дүрэм

**A1. GL рүү нэг л хаалга.** Ямар ч модуль `JournalEntry`-г шууд үүсгэхгүй. Зөвхөн
`ledger.post_entry(company_id, lines, source_ref)`. Тест: `grep -rn "JournalEntry(" src/`
нь `ledger.py`-аас өөр газар олдвол CI унана.

**A2. Мөнгө хэзээ ч float биш.** `amount_minor: bigint` (мөнгөн тэмдэгтийн 1/100).
Хилийн давхаргад (PosAPI, QPay, экспорт) л Decimal-аар хөрвүүлнэ.
*Аудитын сургамж: `amount_currency` Float хэвээр байгаа — засах.*

**A3. Чимээгүй алгасалт хориотой.** Данс олдохгүй бол `_require_account()` алдаа
шиднэ, `if acc: post()` хэв шинж хориотой. 200 OK буцаад журнал бичигдээгүй
тохиолдол = блокер.

**A4. Түрээслэгчийн тусгаарлалт зөвхөн `get_owned()`-оор.** `entry_id`, `item_id`,
`counterparty_id` гэх мэт бүх гадаад ID-г компанийн эзэмшлээр шалгана.
IDOR exploit тест CI-д заавал ногоон байна.

**A5. Тест ногоон = зөв гэсэн үг биш.** Мөнгө хөдөлгөдөг бүх endpoint-д
**GL-assertion тест** (өмнөх/дараах trial balance зөрүү) заавал байна. Зөвхөн
HTTP 200 шалгасан тест хүлээн авагдахгүй.

## 5. AI давхарга — гол ялгарал

> ОЧ 7.7-гийн AI = **тайлан уншиж тайлбарлах**. Bayan-ий AI = **тайланг үүсгэх хөдөлмөрийг
> арилгах** + тайлбарлах. Энэ ялгааг бүтээгдэхүүний гол мессеж болгоно.

### 5.1 L1 — Өгөгдөл оруулалтын автоматжуулалт (ОЧ-д БАЙХГҮЙ)

**Оролт:** банкны хуулга (Excel/XLS/PDF/зураг), eBarimt падаан, нийлүүлэгчийн нэхэмжлэх.

**5 шатлалт pipeline (аль хэдийн хэрэгжсэн, өргөтгөнө):**

1. **Формат fingerprint** → YAML registry-ээс descriptor сонгох (одоо 5 банк)
2. **3 замт задлалт:** А=Excel детерминистик · Б=PDF хүснэгт · В=Fable 5 vision (2-pass)
3. **Нормчлол** — каноник `bank_txn` схем, `amount_minor`, `canonical_hash` (3 давхар dedupe)
4. **⚠️ Validation gate V1–V6 — математик хаалт.** Гол нь **үлдэгдлийн гинжин инвариант**:
   `өмнөх үлдэгдэл ± гүйлгээ = дараагийн үлдэгдэл`. Давахгүй бол ангилалт руу ОРОХГҮЙ.
   *Энэ бол LLM-ийн тоон алдааг математикаар барих цорын ганц найдвартай арга —
   тестээр батлагдсан (ST_413108778 дутуу export-ыг gate зөв илрүүлсэн).*
5. **AI ангилалт** — Haiku 4.5 массаар → итгэл бага бол Fable 5 рүү эскалаци.
   Компани бүрийн few-shot RAG санах ой (өмнөх баталсан ангилалтууд).
   Итгэлцлийн 3 сагс: **авто-батлах / нябо хянах / заавал гараар**

**Хүлээн авах шалгуур:** 3 сарын ашиглалтын дараа авто-ангилалт ≥92%, validation gate
алдаа алдалт 0 (математик хаалт тул).

### 5.2 L2 — Таамаглал (ОЧ-гийн зарласантай ижил, гэхдээ нотолгоотой)

- Борлуулалтын таамаглал: харилцагч × барааны ангилал × сар
- Мөнгөн урсгалын 13 долоо хоногийн таамаглал (авлагын түүхэн зан төлөв дээр)
- Худалдан авалтын хэрэгцээ (M5.5, M8.4-тэй холбогдоно)
- Агуулахын хөдөлгөөнгүй/илүүдэл нөөцийн эрсдэл

**[Д] Заавал биелэх дүрэм:** таамаглал бүр **backtest-ийн үзүүлэлтээ хамт харуулна**
(MAPE, сүүлийн 6 сарын алдаа). Тоо ганцаараа гарахгүй.
*ОЧ «+18%» гэж харуулдаг ч ямар нарийвчлалтай нь тодорхойгүй.*

**Технологи:** энд LLM ХЭРЭГГҮЙ. Сонгодог арга (улирлын задаргаа, gradient boosting).
LLM зөвхөн үр дүнг үгээр тайлбарлахад.

### 5.3 L3 — Удирдлагын асуулт-хариулт (ОЧ-гийн Q&A-гийн зөв хувилбар)

**Асуудал:** LLM-д DB өгвөл (a) буруу SQL, (b) хий үзэгдэл тоо, (c) эрхийн зөрчил гарна.

**Bayan-ий шийдэл — semantic layer, түүхий SQL БИШ:**

```
Хэрэглэгчийн асуулт
   ↓
LLM → бүртгэгдсэн МЕТРИКийн дуудлага болгон хөрвүүлнэ
      (жишээ: revenue(period="2026-07", compare="yoy", dim="customer"))
   ↓
Метрик каталог — гар бичсэн, тестлэгдсэн SQL + GL данс/томьёо
   ↓
Эрхийн шүүлт (§6.3) — хэрэглэгчийн харах эрхтэй мөр л буцна
   ↓
Тоо ledger-ээс шууд гарна → LLM зөвхөн ҮГЭЭР тайлбарлана
   ↓
Хариулт + «энэ тоо ямар журналаас гарсан» drill-down холбоос
```

**[Д] Хатуу дүрэм:**
- **AI хэзээ ч тоо зохиохгүй.** Бүх тоо метрик каталогаас. LLM-д тоо тооцоолуулахгүй.
- Метрик каталогт байхгүй асуултад «Би энэ тайланг мэдэхгүй» гэж хэлнэ (таамаглахгүй).
- **AI-ийн бүх асуулт audit log-д** орно — хэн, хэзээ, юу асуусан, ямар метрик дуудсан.
- **AI нь хэрэглэгчийн эрхээс давж харахгүй.** Няравын асуултад цалингийн мэдээлэл
  ХЭЗЭЭ Ч буцахгүй. Тест: эрх багатай хэрэглэгчийн нэрээр 50 сэжигтэй асуулт
  (red-team suite) CI-д гүйнэ.
- Өгөгдөл гадагш явах эсэхийг **компани бүр тохируулна**: (a) зөвхөн дотоод загвар,
  (b) vendor API руу маскалсан агрегат, (c) бүрэн. Default = (b), тохиргоо ил.

### 5.4 L4 — Гажилт илрүүлэлт **[Д]**

Хоногийн багц: давхар төлөлт, сэжигтэй харилцагч, дансны буруу хослол (жишээ:
түлш → 2101 Түүхий эд), НӨАТ-ын зөрүү, цалингийн гажилт (M4.6).
*Аудитын түүхээс: «зээлийн хүү → 7101 Цалин» гэх мэт алдаа хүн шалгахгүй бол үлддэг.*

## 13. Инженерийн засаглал (аудитын 4 тойргоос сурсан)

Эдгээр нь зөвлөмж биш, **гэрээ**:

1. **Код өөрчлөгдсөн бүрд `pytest` — улаан бол цааш явахгүй.** CI-д заавал.
2. **Тест ногоон = зөв гэсэн үг биш.** Шинэ endpoint тестгүй бол ногоон харагдана.
   Тиймээс: мөнгө хөдөлгөх endpoint бүрд GL-assertion тест байхгүй бол PR нэгдэхгүй.
3. **Endpoint 200 буцаасан нь шалгалт биш.** Өмнөх/дараах trial balance зөрүүг харьцуул.
4. **Дансны кодын НЭР солиход** түүнийг ашигладаг бүх модулийг шалга:
   `grep -rn "<код>" src/`. (5105-ийн регресс ингэж гарсан.)
5. **AI-аар код бичүүлсэн бол заавал аудит** — FIXME-*.md даалгавар болгож repo-д тавихад
   бүрэн гүйцэтгэгддэг нь батлагдсан.
6. **`api.py` 5,865 мөр / 197 endpoint нэг файлд байх нь блокер.** Модуль бүрийг
   өөрийн router-т задлана. Үе 0-д хийнэ.
7. **Төсөл git repo байх ёстой**, `.env` gitignore-д.
8. Нэг функцийг устгаж нэрлэхээ өөрчилбөл **дуудагдаж буй бүх газрыг** заавал шалга
   (`post_journal_entry`→`post_entry` хэрэг 9 endpoint унагасан).

2. Одоогийн хоёр зэрэгцээ систем — Python/FastAPI ба `bayan ai/` доторх Next.js+Prisma —

3. Зорилтот сегмент: ОЧ-гийн харилцагчид (том FMCG холдинг) уу, эсвэл тэдэнд хэт үнэтэй
   санагдаж байгаа дунд бизнесүүд үү? *(Зөвлөмж: сүүлийнх — өрсөлдөөн бага, AI-ийн
   үнэ цэн тэнд илүү мэдрэгдэнэ.)*
4. AI-ийн inference: бүрэн дотооддоо host хийх үү, vendor API ашиглах уу? Энэ нь
   «өгөгдөл гадагш гарахгүй» гэсэн маркетингийн мэдэгдлийг шууд тодорхойлно.
